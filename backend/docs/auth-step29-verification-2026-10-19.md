## Экран и интеграция

Отдельная фабрика app.auth_ui.create_auth_ui оборачивает существующий ProtectedApp. Экран /login оформлен в палитре Техресурс: светлый фон, белая карточка, бирюзовый фирменный акцент, адаптивная ширина и русские подписи. Основные экраны сохраняют прежнюю разметку: оболочка добавляет только CSS/JS авторизации в сформированный HTML корневой страницы.

Точный публичный список оболочки: GET /login, GET /auth-ui.js, GET /auth-ui.css. Остальные пути проходят прежнюю политику 163 маршрутов; неизвестные операции запрещены. Это три явно разрешённых ресурса интерфейса, а не публичный static mount. Анонимный GET / перенаправляется на /login; API возвращают 401.

Вход использует POST /api/auth/login, текущий пользователь и разрешения — GET /api/auth/me, выход — POST /api/auth/logout. Сессия остаётся серверной, HttpOnly cookie устанавливает прежний API. Пароли, cookie-токены и CSRF не сохраняются в localStorage/sessionStorage. Пароль очищается после каждой попытки; форма имеет method=post, поэтому запасная нативная отправка не помещает пароль в URL. Кнопка доступна после установки обработчика.

CSRF хранится только в замыкании JS и добавляется к изменяющим same-origin fetch. Внешним адресам CSRF не передаётся. 401 очищает состояние страницы и переводит на вход, 403 показывает нейтральное сообщение о недоступном действии. Сессия перепроверяется при возврате к вкладке и раз в минуту; API немедленно проверяет её при каждом запросе. Ошибка проверки сессии блокирует интерфейс, а не назначает анонимную роль.

## Права интерфейса

Источник — roles и permissions из БД через /api/auth/me; должность и клиентский employee_id не определяют полномочия. Оператору выводятся логин, роль и кнопка выхода.

OFFICE_MANAGER: просмотр, навигация, фильтры и Excel; кнопки создания, редактирования, загрузки и формирования скрыты. Редакторы матрицы отключены, значения доступны для просмотра.

SYSTEM_TECHNICIAN: доступны согласованные операции создания/изменения, одиночная загрузка билета, загрузка ежедневного отчёта, формирование ЛУВР и ВОУ. У обеих ролей скрыты удаление, подтверждение, аннулирование, восстановление, настройки и согласование/правила распознавания. Обработка серверных папок также скрыта. Выбор PDF ограничен одним файлом, как требует политика шага 28.

Ограничения применяются к существующим ID/классам и названиям действий; MutationObserver обрабатывает появляющиеся элементы. Основная навигация, вкладки, возврат и экспорт сохраняются. Этот UI-слой не является границей безопасности: backend продолжает независимо проверять маршрут, роль, разрешение, CSRF и смешанные ветви операции. Новые и переименованные элементы интерфейса требуют соответствующей проверки селекторов; автоматическая классификация по надписям сама по себе не доказывает полномочия.
