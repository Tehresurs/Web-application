## Механизм и результат модуля

`prepare_month(year, month)` вызывает существующий
`production_matrix.calculate_month()` — без нового распределения времени.
Метаданные и подтверждённые источники читаются отдельной READ ONLY транзакцией.
Отдельная чистая функция `prepare_data(matrix, positions, categories, confirmed_facts)`
доступна для тестов и будущего использования подготовленного снимка данных.

`share_cents` каждой дневной ячейки переносится целиком как целое число сотых
человеко-дня. Не используются месячные total_cents и source строки, поскольку
одна строка матрицы бывает MIXED. Отбираются только дневные source=FACT,
report_received=true с существующим source_fact_id, соответствующим сотруднику
и календарной дате в daily_control_results. Само наличие там записи — сохранённый
подтверждённый ежедневный факт, отдельного статуса подтверждения в этой таблице нет.

Исключения применяются до группировки и итогов:

- должность ID=17 «Инженер СК СЛ»;
- is_dk=true или excluded_from_production=true;
- любые PLAN, включая камеральный план.

Нулевой подтверждённый факт сохраняется как нулевое значение с происхождением,
не превращается в план и не увеличивает сумму.

Группировка: категория на дату → сотрудник → объект/подобъект → aos_description.
Для новой модели объектов используется entity_id, иначе пара object_id/subobject_id.
Разные ПО/субподрядчики одного объекта не создают повторного рабочего дня:
суммируются только готовые отдельные доли исходных фактов, каждый факт один раз.
Повтор (employee_id, date, source_fact_id) приводит к ошибке, а не двойному учёту.
Разные объекты остаются отдельными строками, но строки сотрудника идут подряд.
Для аудита каждая строка хранит sources с датой, fact_id и исходной долей.

## Категории и историчность

Категория берётся именно из каждой датированной ячейки существующей матрицы.
Текущие employee_assignments, категория ПО или текущая категория объекта
для подстановки не запрашиваются.

Исходный daily_control_results.category_id сохранён при подтверждении.
Существующая матрица дополнительно применяет действующие на дату CATEGORY
корректировки через production_matrix_overrides.resolve(). Эти готовые
корректировки сохраняются: иначе ВОУ разойдётся с матрицей.
Если category_id ячейки отличается от подтверждённого без applied_overrides.CATEGORY,
подготовка прекращается как FACT_CATEGORY_MISMATCH. В sources сохраняются оба ID
и идентификаторы применённых корректировок.

В реальном октябре 4 таких корректировки:

| Факт | Подтверждённая категория | Категория матрицы | CATEGORY override |
|---:|---:|---:|---:|
| 204 | 5 | 1 | 139 |
| 326 | 3 | 1 | 122 |
| 182 | 3 | 1 | 123 |
| 374 | 3 | 1 | 157 |

У 7 сочетаний сотрудник/объект категории различаются по датам месяца.
Данные по датам сохраняются раздельно, текущим назначением не заменяются.

Сопоставление разделов фиксируется по ID: 1–5 — основные разделы;
ID 6 — основной раздел «Прочие»;
ID 7/8/9 с parent_id=6 — подразделы 6.1/6.2/6.3.
Иерархия проверяется, при изменении выдаётся ошибка.

Подкатегории 6.4 сейчас **нет**. Модуль предусматривает пустой подраздел с
category_id=None и предупреждением SUBCATEGORY_6_4_NOT_IN_DIRECTORY.
Он не создаёт запись БД и не переносит факты категории 6 в 6.4 автоматически.
Если впоследствии появится единственная дочерняя категория parent_id=6,
sort_order=4, используется её реальный ID; совпадение названия не используется.
Факты с несопоставленной категорией, в том числе непосредственно ID 6,
останавливают подготовку. Для их обработки потребуется согласование.
В текущем октябре фактов ID 6 нет, поэтому сумма из-за отсутствия 6.4 не теряется.

Названия объектов, Ф.И.О., должности и aos_description — доступные текущие
значения справочников. Исторических снимков этих текстов/должностей на дату
в источнике нет. Требование брать дневную категорию соблюдается по ID и
существующим датированным корректировкам; историческое восстановление всех
текстовых реквизитов этим этапом не заявляется.

Матрица и метаданные загружаются двумя read-only снимками. Рассогласование
удалённого/изменённого источника выявляется сверкой ID, даты, сотрудника и
категории; единый атомарный снимок всех справочных текстов не гарантируется.
