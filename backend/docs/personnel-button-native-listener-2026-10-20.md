# Ускорение активации кадровой кнопки, 20.10.2026

По отдельному разрешению пользователя заменена только серверная проверка listener в app/services/personnel_local.py: вместо запуска PowerShell на каждом запросе читаются свежие IPv4/IPv6 TCP-таблицы Windows GetExtendedTcpTable (OWNER_PID_LISTENER). Кэширования результатов нет. На 8001 должен существовать только IPv4 listener 127.0.0.1 текущего PID; чужой PID, внешний/IPv6 listener, отсутствие записей и ошибки API дают отказ. При росте таблицы чтение повторяется ограниченно; неполный буфер не принимается. Origin, read-only, Host, Fetch Metadata, процессные ключи и входные проверки не менялись.

Пройдено 19 тестов, включая реальное сравнение результата native API с Get-NetTCPConnection, смену состояния между последовательными вызовами, отказы при внешнем/IPv6 адресе, чужом PID и ошибке API, существующие проверки запросов. PowerShell остался только в сравнительном тесте, не в обработке запросов приложения.

Существующий 8001 перезапущен тем же локальным launcher; порт и БД сохранены. Штатный запуск ротирует только служебный digest процессного ключа. Миграции, исторические записи, Матрица, ЛУВР и операции перемещений не изменялись.

Реальный браузер, три карточки: до ускорения активация 2423/1452/1555 мс; после — 250/352/343 мс. Кнопка существует синхронно, остаётся тем же DOM-элементом, положение неизменно. По два прежних запроса на карточку, без дополнительных запросов. Формы TRANSFER/ASSIGN/END открываются, JS-исключений нет. Сохранение кадровых операций в этих проверках не выполнялось, чтобы не менять данные.
