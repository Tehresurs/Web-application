# ДК — Дубль-контроль (8001)

Текущий однопользовательский режим: руководитель. Серверная переменная
TEHRESURS_USER_ROLE=LEADER (значение по умолчанию). Любая другая роль запрещает
изменение ДК (403), интерфейс скрывает действия. Это настройка экземпляра,
не многопользовательская авторизация. Клиент не передаёт роль.

Миграция 029_matrix_dk.sql применяется только к ai_excel_agent_test,
схема test_construction_identity_stage46. production_matrix_dk хранит employee_id
и work_date с составным первичным ключом. История изменений не ведётся.
Триггеры отмечают изменения источников календаря; MatrixConnection пересчитывает
допустимость ДК перед commit, включая connection.transaction(). Нерабочий день,
больничный, отсутствие, архивирование или смена должности снимают событие.
Восстановление рабочего дня не возвращает отменённое ДК.
Прямой SQL через внешний клиент обходит Python-проверку: изменения источников
должны выполняться через приложение 8001 и get_connection().

API:
- GET /api/production-matrix/capabilities — role, can_manage_dk, single_user.
- PUT /api/employees/{employee_id}/production-matrix/dk/{YYYY-MM-DD} — назначить.
- DELETE по тому же адресу — отменить. Обе операции идемпотентны.
- 403 — роль не руководитель; 409 — неподходящая должность, день или состав ЛУВР.

Условия: должность «Инженер ПИЛ (НК, УЗК)», ЛУВР FULL/HALF,
нет отсутствия, сотрудник не архивный и включён в ЛУВР месяца.
В ячейках матрицы is_dk=true, day_event=DK, excluded_from_production=true,
comment=«Проведен ДК», share_cents=0. FACT/PLAN и ссылки на источники сохраняются.
При отсутствии объектных строк есть расчётная строка kind=DK.
Проверки дня и итоги содержат dk_cents: доступное время, исключённое из
производственных итогов. ЛУВР и число рабочих дней неизменны.
Будущий АОС должен исключать excluded_from_production до расчёта всех показателей.
Генератор АОС не создавался. Правила Расстановки не изменялись.

Ручная проверка:
1. Обновить 8001 (Ctrl+F5), открыть Производственную матрицу и сотрудника ПИЛ.
2. Выбрать рабочий день 1 или 0,5, в деталях нажать «Назначить ДК».
3. Проверить фиолетовое «0 ДК», комментарий и сохранение ЛУВР.
4. Добавить подтверждённый отчёт: событие остаётся.
5. Отменить ДК: восстанавливаются актуальные факты или план.
6. Назначить снова, изменить ЛУВР на «Д», затем вернуть рабочий день:
   ДК не возвращается. На нерабочем дне новое назначение запрещено.
7. Другие должности не имеют действия ДК.
8. В отдельной тестовой сессии с TEHRESURS_USER_ROLE=ENGINEER или
   SYSTEM_TECHNICIAN кнопки отсутствуют, PUT/DELETE возвращают 403.

Автоматические проверки: tests/test_matrix_dk.py; тестовые изменения БД откатываются.
