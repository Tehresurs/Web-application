# Этап 4: известные соответствия

Существующие `match_employee`, `match_object`, `match_po` используют порядок:
точное совпадение → `resolve_value_alias` → прежний fuzzy matching → новое значение.
Пороги не изменены. Подобъекты в эту цепочку не включены.

При alias результат содержит `status: found`, `match_source: alias`, целевую
запись и пустой список кандидатов. `prepare_report` сохраняет исходные поля
и передаёт `resolved_employee`, `resolved_object`, `resolved_general_contractor`
или `resolved_subcontractor`. Существующая логика Журнала использует целевые ID.
Событие `ALIAS_MATCH` записывается на уровне INFO.

В строке ПОХОЖЕЕ пользователь выбирает кандидата, при необходимости отмечает
«Запомнить соответствие» и нажимает «Выбрать и заменить». Без отметки запрос
создания alias не отправляется. С отметкой POST `/api/value-aliases` получает
исходное значение без нормализации в браузере. При конфликте выбор остаётся
для текущего отчёта, а сообщение сообщает, что соответствие не сохранено.
Существующий alias не перезаписывается. Добавление новой записи не создаёт alias.

Примеры запросов (ID условные, цели должны существовать):

```json
{"entity_type":"employee","source_value":"Кецких Игорь Валерьевич","target_id":17}
```

Цель: «Кетских Игорь Валерьевич».

```json
{"entity_type":"object","source_value":"Обустройсто куста №55","target_id":15}
```

Цель: «Обустройство куста №55».

```json
{"entity_type":"po","source_value":"ООО «СтройСервс»","target_id":3}
```

Цель: «ООО «СтройСервис»».

## Ручная проверка

1. Взять Word с опечаткой «Кецких Игорь Валерьевич», для которой ещё нет alias,
   при наличии правильной записи «Кетских Игорь Валерьевич».
2. Обработать файл и открыть проверку: ожидается ПОХОЖЕЕ.
3. Выбрать правильного сотрудника, отметить «Запомнить соответствие».
4. Нажать «Выбрать и заменить», дождаться сообщения о сохранении.
5. Повторно обработать исходный Word.
6. Ожидать ИЗВЕСТНОЕ СООТВЕТСТВИЕ, исходное ФИО и отдельно правильное ФИО.
   Кнопок согласования нет; employee_id соответствует правильному сотруднику.
7. Повторить для объекта, генподрядчика и субподрядчика.

Word и основные справочники не переименовываются. Схема БД, Журнал,
его уникальность и employee_assignments не изменены.
