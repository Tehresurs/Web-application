# Удаление ошибочного назначения И.О.

На 8001 в кадровой истории добавлена явная кнопка «Удалить назначение И.О.» с должностью и периодом соответствующего назначения. Диалог показывает выбранную запись, требует причину и отдельное подтверждение удаления. Используется существующая команда CANCEL; физического удаления истории нет. После отмены назначение не участвует в датированных расчётах, аудит остаётся с исходным источником. Origin, процессный ключ, read-only, версия истории и защита повторов сохранены.

Новая миграция и перезапуск не требовались: изменены только employee_transfers.js и версия его подключения в processing.html. Уже завершённое И.О. со связанным планом не получает кнопку удаления: существующий запрет защищает план и не ослаблялся.

Через реальный браузер на 127.0.0.1:8001 на ранее обозначенном синтетическом сотруднике сохранены ASSIGN и CANCEL. Проверены исчезновение кнопки для отменённого назначения, сохранение истории, LOCAL_APP/actor NULL, неизменность основной должности ID 3 и прежнего плана ID 18; JS-исключений нет. SQL personnel_acting_at на тестовую дату вернул NULL. Тестовый сотрудник повторно архивирован и не включён в рабочий месячный ЛУВР. Реальные назначения пользователя не отменялись.

Артефакт: browser_acting_cancel.json в каталоге output/security/personnel_local_current.txt. Новый браузерный сценарий: tests/browser/personnel_acting_cancel_live.cjs. node --check кадрового JS успешен.
