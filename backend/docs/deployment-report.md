## Источники и правила

`app.services.deployment.get_report()` вызывает существующий `production_matrix.calculate_month()` напрямую. Даты внутреннего календаря имеют тип Python `date`; сравнение выполняется по ISO-дате. Нового алгоритма ЛУВР или плана нет.

Для каждого сотрудника отдельно выбираются FACT выбранной даты, при отсутствии — PLAN. Состав ограничен сформированным месяцем ЛУВР и итоговыми FULL/HALF: каждый сотрудник считается один раз независимо от половины дня и числа объектов. Отдельный фильтр по тексту названия должности не вводился.

Объектные строки берутся из ячеек матрицы; одинаковые сочетания сотрудника, объекта, подобъекта и отображаемой организации группируются только для договорного представления. Исходные ячейки остаются в `sources`. Организация — субподрядчик при наличии, иначе ПО. Итог организаций считается по уникальным ID именно отображаемых организаций. Объекты — уникальные родительские object_id; подобъекты не увеличивают этот итог.

Без конкретного объекта выводится «Все объекты контроля», без выдумывания назначения в БД. Неизвестное назначение дополнительно отмечается предупреждением и не объявляется камеральным. Факты при нерабочем коде исключаются из обычной расстановки, но возвращаются целиком в предупреждениях. Несформированный месяц возвращает `formed=false`, `totals=null`; экспорт отклоняется с HTTP 409.

## API

- `GET /api/deployment/report?date=YYYY-MM-DD` — дата, семь колонок, строки с источниками, итоги и предупреждения.
- `GET /api/deployment/report/export?date=YYYY-MM-DD` — XLSX по тому же сервису, без записей в БД.

Excel содержит договорную шапку, дату, семь колонок, строки и три итога. Нет легенды, подписей и вымышленных распоряжений. Значения пользовательских полей записываются как текст, не как формулы. Экспорт формирует актуальный отчёт заново.

## Ограничения

Реквизиты сотрудников, должностей и экипажей текущие, не исторические снимки. Расчёт матрицы и чтение контактов выполняются существующими соединениями, поэтому одновременное изменение справочника может отразиться в контактах уже после расчёта матрицы. Неполные реквизиты остаются пустыми и сопровождаются предупреждениями. Описания должностей доступны в API; дополнительные колонки сверх семи утверждённых не добавлялись. Номер/дата распоряжения и сведения о собственности автомобиля не заполняются согласно заданию.

Миграций нет. Расчёты ЛУВР, матрицы, подтверждение ежедневных отчётов, билеты и парсеры не изменялись.
