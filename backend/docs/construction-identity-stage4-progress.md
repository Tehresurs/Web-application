## Подэтап 4.3 — закрепления, назначения и билеты

Новые запросы принимают `entity_id`; исходные ID необязательны и не заполняются вымышленными значениями. Старые ссылки разрешаются через тот же resolver. Чтение добавляет текущую иерархию, не подменяя исходные ID. Неизменённые ссылки при редактировании сохраняются. Действующая логика периодов и рабочего времени не менялась.

Кандидат 024 снимает NOT NULL только с `employee_assignments.object_id` и `production_assignment_items.object_id`. FK остаются; триггер требует реальную ссылку, проверяет согласованность совместно переданных ID, архив и активность. Старый триггер родительской принадлежности заменён проверкой идентичности. Старый UNIQUE набора производственных объектов заменён канонической проверкой дублей, учитывающей исторические строки с пустым `entity_id`; прочие ограничения сохранены. Исторического заполнения `entity_id` нет.

Создание исходной записи автоматически регистрирует идентичность и текущего родителя в той же транзакции. Структурные изменения и архивирование сериализуются общей блокировкой. В билетах `entity_id` включён в ревизию источника только при его наличии, поэтому прежние ревизии остаются совместимыми. Синхронизация билета с назначением не создаёт фиктивный объект; аннулирование и восстановление сохраняют существующую связь.

## Подэтап 4.4 — факты и отчётные потребители

14.10.2026. Новые подтверждения принимают `entity_id`. Сохранение проверяет назначения и действующие обязательные поля; архив остаётся предупреждением для достоверного запоздавшего отчёта. Старые ссылки разрешаются без обновления строк. Проверка повторного факта учитывает каноническую идентичность, дату, сотрудника, ПО, субподрядчика и категорию, включая старые строки без `entity_id`.

Матрица получает текущие названия и иерархию отдельно от исходных фактов. Перенос не меняет ревизии фактов и ручные корректировки. Nullable `entity_id` исключается из исходной ревизии старого факта, чтобы само применение 024 не сделало прежние корректировки неактуальными. Распределение времени и состав работающих не менялись. Группы журнала, матрицы и Расстановки различают самостоятельные сущности по `entity_id`, даже при общем родителе. Подтверждённые Word-отчёты по-прежнему считаются по SHA-256 источника; прогноз использует пары сотрудник–сущность контроля.

GET объектов в схеме 024 возвращает текущие самостоятельные сущности, GET подобъектов — текущих детей; доступен фильтр `parent_entity_id`. Исходные ID не заменяются ID из другой таблицы. Сопоставление названий и старых aliases использует устойчивую идентичность и текущую иерархию; исходный текст Word не переписывается. Excel Расстановки получает те же строки, что экранный отчёт, и сохраняет семь колонок.

В кандидат SQL дополнительно внесены nullable `daily_control_results.object_id`, проверка ссылки и дублей факта, nullable `construction_subobjects.object_id` и `initial_parent_entity_id` для исходного родителя новых записей. Последующее перемещение меняет только текущую иерархию. Старые FK сохраняются. Runner сравнивает все существовавшие до запуска столбцы. Исправлен повторный запуск после преобразований: начальное заполнение пропускает уже зарегистрированные строки иерархии.
