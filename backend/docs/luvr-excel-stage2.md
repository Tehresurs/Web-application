## API и порядок

Основной запрос кнопки:

```http
POST /api/luvr/month/export
Content-Type: application/json
```

```json
{"year":2026,"month":10,"employee_ids":[45,18,72,6]}
```

Это иллюстрация контракта, а не полный октябрьский состав. Frontend собирает ID из `#luvrMonthBody tr[data-employee]` в текущем видимом порядке. Итоговая строка расположена отдельно и в список не входит. Backend требует точного совпадения множества ID с составом месяца, запрещает повторы, посторонние/пропущенные ID и нецелые значения. Несоответствие состава — 400 с просьбой обновить ЛУВР; неверные типы — 422.

GET `/api/luvr/month/export?year=2026&month=10` сохранён как явно определённый fallback: используется существующий порядок monthly repository (нормализованное ФИО, затем employee_id). Exporter его дополнительно не сортирует. Имя файла обоих маршрутов — `ЛУВР_YYYY-MM_этап2.xlsx` с ASCII fallback в Content-Disposition.

## Mapping и проверки

| Область | Заполнение |
|---|---|
| Q2, A5, F7 | Без изменений логики этапа 1, snapshot месяца |
| F8:AJ8 | Даты выбранного месяца в прежнем формате; отсутствующие дни пустые |
| A9:AM84 | Сначала очищаются значения, затем заполняются только сотрудники membership |
| A | Порядковый номер 1..N согласно переданному порядку |
| B / C / D / E | Полное ФИО / должность / НРС / специальность |
| F:AJ | Готовые FINAL-значения дней |
| AK / AL / AM | work_days_total / downtime_days_total / travel_days_total |
| F85:AJ85 | Готовый work_equivalent каждой реальной даты |
| AK85 / AL85 / AM85 | Суммы соответствующих итогов сотрудников |

НРС NULL/пустой/пробельный → «Нет». Непустое значение сохраняется как есть. Пустая специальность блокирует экспорт с перечислением ФИО. 77 и более сотрудников блокируют экспорт без обрезания списка. Отсутствующие дни и неиспользованные строки пустые, включая старые формулы и итоги в A9:AM84. Строки и колонки не добавляются и не удаляются.

FULL → числовое 1; HALF → числовое 0.5; TRAVEL → Д; OFF_SHIFT → МВ; DOWNTIME → П; DISMISSED → Уволен; EMPTY → пусто. Exporter не интерпретирует sickness, UNKNOWN или dismissal самостоятельно. Все они уже учтены в FINAL. Например, auto FULL с override DOWNTIME переносится как П.

Перед записью проверяются полнота дат и равенство суммы рабочих итогов сотрудников сумме дневных итогов. Выходное AK85 равно обеим суммам. Итоги берутся из того же месячного результата, что использует веб-ЛУВР; старые формулы MASTER не используются для их расчёта.

openpyxl сериализует значения. Затем заменяется только XML разрешённых ячеек с сохранением исходных style IDs. Все остальные ZIP-части и XML вне разрешённых ячеек сохранены байт-в-байт. Размеры, объединения, стили, границы, print area/page setup не меняются.

## UI

ФИО — кнопка открытия существующей карточки по employee_id, включая архивных сотрудников. ФИО и номер строки не используются как ключ. Пустая специальность отображается как «Не указана» с цветом ошибки и подсказкой исправить связанную должность. Поля должности в карточке остаются существующими, отдельного редактора specialty не создавалось.

Событие `employee-saved` обновляет текущий месяц без повторного формирования состава. Сортировка сохраняется. Календарные кнопки продолжают редактировать день, заголовки — сортировать, ФИО — открывать сотрудника. Экспорт передаёт текущий видимый порядок и блокирует повторное нажатие на время скачивания.
