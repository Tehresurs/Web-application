## Механизм

1. Официальный POST получает снимок только сохранённых реквизитов.
   Без полного набора возвращается HTTP 409 с перечислением отсутствующих полей,
   до получения данных/запуска Excel/публикации.
2. Используется существующий prepare_month Б2 и тот же READ ONLY снимок БД.
   Необязательный with_context=True дополнительно возвращает уже рассчитанную
   матрицу и должности. Прежний вызов/результат prepare_month не изменён;
   перерасчёта или нового распределения времени нет.
3. B3 формирует расположение строк из готовых долей Б2.
   Шесть разделов, четыре подраздела 6.1–6.4, согласованный порядок ID/ФИО.
   Сокращение и расширение блоков выполняется снизу вверх, не перезаписывает
   последующие разделы и подписи. В контроле 281 строка объектов,
   включая три полностью пустые строки объектов, имевших в месяце только ДК.
4. Существующий B1 COM lifecycle сохранён: новый изолированный скрытый Excel,
   AutomationSecurity=3, события отключены, UpdateLinks=0, макросы не запускаются,
   сохранение копии, закрытие/повторное открытие, проверка VBA/профилей принтеров,
   освобождение COM и контроль завершения только собственного Excel PID.
   Добавлены ограниченные операции раскладки и пакетное чтение значений.
5. Строки и итоги заполняются разрешёнными локальными SUM-формулами.
   Округление и распределение не повторяются. AL очищается и не заполняется.
6. Проверяются значения всех дневных ячеек в повторно открытом Excel,
   итоги строк/подразделов/разделов/отчёта, формулы и отсутствие содержимого
   нулевых/ДК ячеек в XML. Проверяются VBA, рисунки/управление и печать.
7. Только официальный успешный результат передаётся VouArchive.publish.
   Технический результат имеет technical_only=true и дополнительно запрещён
   самим архивом, даже при наличии временных заполненных реквизитов.

Исходный шаблон не перезаписывается, openpyxl для сохранения не используется.
Принятый механизм восстановления целых печатных профилей и PrintArea не заменён.
Коллатирование/драйверы не перенастраивались вручную.

## API и интерфейс

«Отчет ВОУ» → выбор месяца/года → «Сформировать Отчет ВОУ».
POST /api/vou/reports {year,month} формирует/проверяет официальный файл,
сохраняет его через VouArchive и возвращает ID и предупреждения.
Параллельный повторный запуск в одном процессе блокируется.
Клиент показывает ход формирования и ссылку скачивания после успеха.

Скачивание: GET /api/vou/reports/{id}/file, с проверкой целостности.
Повторное формирование — новый UUID, прежние документы не переписываются.
Пользовательские настройки не перечитываются после формирования вместо снимка.
Внешний POST не принимает реквизиты или technical_only: только год и месяц.

На действующем 8001 проверен отрицательный сценарий: пять реквизитов пусты,
показано полное предупреждение, архив остался пустым, JavaScript-ошибок нет.
Официальный положительный POST/скачивание через архив отложены пользователем;
технический XLSM/PDF проверены непосредственно через тот же render/COM код.
