# Этап 2 — управление составом экипажей

13.10.2026.

Использована существующая связь `employees.crew_id → crews.id`. Миграций нет.

В карточке экипажа добавлены состав (ФИО, должность, количество), поиск по ФИО, множественный выбор, закрепление и исключение. Кандидаты показывают текущий экипаж; перевод требует явного подтверждения. Архивные сотрудники видны в существующем составе, но не предлагаются для нового закрепления. После сохранения обновляются состав и существующий список сотрудников, включая карточку сотрудника.

## API

`PATCH /api/crew-memberships`:

```json
{
  "target_crew_id": 2,
  "employees": [{"employee_id": 7, "expected_crew_id": 1}],
  "confirm_transfers": true
}
```

`target_crew_id: null` исключает из экипажа. Для каждого сотрудника обязательно передаётся прежний экипаж, включая null. Отсутствующие записи возвращают 404; устаревшее закрепление или неподтверждённый перевод — 409. Повторяющиеся ID отклоняются. Неизвестные поля запрещены.

Операция блокирует выбранные строки сотрудников в порядке ID, проверяет всю группу и меняет только `crew_id` одной транзакцией. Целевой экипаж защищён от конкурентного удаления. Ошибка откатывает всю группу. При конфликте интерфейс перечитывает сотрудников, сбрасывает выбор и требует нового решения. Состав не хранится отдельно: список формы — временный снимок существующего API сотрудников для проверки прежних закреплений.
