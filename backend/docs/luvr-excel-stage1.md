Это сохраняет shared formulas, кеши формул и остальные XML-части байт-в-байт; обычное сохранение всей книги через openpyxl могло бы изменить их представление. Стили исходных ячеек сохранены. MASTER только читается.

## Настройки и snapshot

UI «Настройки ЛУВР»: должность, ФИО, многострочный заголовок. Слово «Утверждаю» не редактируется. Изменение настроек влияет только на будущие сформированные месяцы.

Миграция `010_luvr_header.sql` создаёт singleton-таблицу `luvr_settings` и три snapshot-колонки в `luvr_months`. Для ранее созданных месяцев без snapshot выполнена однократная инициализация начальными настройками при миграции; это не восстановление неизвестных исторических настроек. Уже существующий snapshot не переписывается. Новые месяцы получают snapshot в том же INSERT и транзакции, что формирует месяц. Повторное формирование использует ON CONFLICT DO NOTHING.

GET, экспорт, расчёт, редактирование дней и состава не обновляют snapshot. Runner `python -m app.database.migrate_luvr_header` применён к рабочей БД. Он транзакционный, с advisory lock и ограничением ожидания блокировки. Старые миграции и факты ЛУВР не менялись.

## API

- GET /api/luvr/month/settings — текущие настройки.
- PUT /api/luvr/month/settings — сохранить три настройки, пустые значения отклоняются.
- GET /api/luvr/month/header-snapshot?year=2026&month=10 — snapshot сформированного месяца.
- GET /api/luvr/month/export?year=2026&month=10 — изменён: только этап 1, Content-Disposition с русским именем и ASCII fallback.

Кнопка disabled для несформированного месяца; tooltip «Сначала сформируйте ЛУВР за выбранный месяц». Для сформированного месяца скачивается `ЛУВР_YYYY-MM_этап1.xlsx`; даже пустой состав допустим, поскольку таблица сотрудников на этом этапе не заполняется.
