# ЛУВР: дата увольнения при формировании состава

Исправление 03.10.2026, только автоматическое первое формирование месяца.

## Диагностика

Единственный автоматический INSERT находится в `app/repositories/luvr_month.py`, `form_month`. Второй INSERT в том же файле относится к ручному добавлению и не менялся. Отдельной команды переформирования состава не найдено; повторное формирование не пересоздаёт сохранённый состав.

Прежнее условие:

```sql
NOT is_archived AND (dismissal_date IS NULL OR dismissal_date >= month_start)
```

Исключение уволенных до начала месяца уже присутствовало. Поэтому отсутствие проверки даты как причина попадания уволенных в следующий месяц не подтверждено. Сохранённый состав мог быть создан до изменения даты увольнения либо дополнен вручную; автоматически исправлять его по новым данным нельзя и не выполнялось.

Подтверждённый дефект: `NOT is_archived` исключал сотрудника из месяца его увольнения, если он уже был архивным на момент первого формирования этого месяца.

Новое условие:

```sql
dismissal_date >= month_start
OR (dismissal_date IS NULL AND NOT is_archived)
```

Если дата известна, она определяет применимость сотрудника к месяцу: ранее первого дня — исключить; в этом или будущем месяце — включить независимо от архива. Если дата NULL, сохраняется прежнее правило архива. Today не используется. Дата увольнения и флаг архива не меняются.

Условие применяется исключительно внутри ветки создания нового заголовка месяца. Уже сформированные составы, snapshot, ручное добавление и удаление остаются прежними. Excel продолжает экспортировать готовый membership без дополнительной фильтрации.
