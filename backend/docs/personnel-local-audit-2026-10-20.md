# Локальный кадровый источник — состояние после автоматического отказа

Миграция 035_personnel_local_audit.sql применена по прямому разрешению пользователя. 033/034 повторно не применялись. Существующая история не удалялась; в трёх журналах добавлен audit_source USER/LOCAL_APP, NULL actor разрешён только для LOCAL_APP. Идемпотентность защищена UNIQUE NULLS NOT DISTINCT (audit_source,actor_user_id,request_id). Пользовательские SQL-команды и путь действительной сессии сохранены.

Перед DDL создана свежая полная before_local.dump; весь архив прочитан pg_restore в NUL, SHA256 сохранён в report.json. Восстановление этой новой копии в новую БД не выполнялось; новых БД/серверов не создавалось. Предварительный прогон DDL полностью откачен. Первый прогон обнаружил порядок снятия PK; ошибочная транзакция откачена, исправленный прогон успешен. Полные архивы и отчёты обеих попыток сохранены.

Подготовлены HR-only capability module и явный launcher run_8001_personnel_local.py на том же 127.0.0.1:8001: отдельные процессные ключи для браузера и SQL, фактическая проверка адреса/PID listener, строгий Host/server/client, Origin, Fetch Metadata, отказ forwarded-заголовков/read-only, JSON и имеющаяся payload-валидация. Проверка listener или Origin в одиночку не разрешает запись. SQL-ключ хранится в БД только как SHA256. Другие API не получают локальный режим. Режим рассчитан на доверенный локальный компьютер, не защищает от его администратора/компрометации ОС. Ключ процесса не выдаётся за пользовательскую сессию.

12 тестов локальной защиты и 130 автономных регрессионных тестов успешны. В существующей БД проведены rollback-only тесты на синтетическом сотруднике: перевод, повтор, конфликт payload, И.О., повтор, завершение с реальным object-планом через существующий save(), повтор, источник «Локальное приложение» без actor, отказ неправильному SQL-ключу. Вся транзакция отменена, пользователей/сессий не создавали. Последовательности после rollback могут иметь пропуски; исходные строки сотрудников и фактов не менялись.

Автоматический контроль отклонил следующую команду активации и перезапуска. Причина: постоянная установка enabled=true/date_readers_verified=true без признанной доказанной проверки датированных читателей расценена как ослабление готовностных проверок. Команда целиком не исполнилась, включая её файловую правку и Stop/Start-Process. Повторной попытки или альтернативного способа включения нет. Ранее один запуск теста получил именно тайм-аут проверки (не отказ по риску); разрешённый инструментом единственный идентичный повтор теста успешно выполнен.
