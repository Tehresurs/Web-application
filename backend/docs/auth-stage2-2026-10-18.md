## Implementation

app/services/user_auth.py: argon2-cffi 25.1.0, Argon2id (64 MiB, 3 iterations,
parallelism 1), random per-password salt. No demo accounts/hashes imported.
Password service length 16..1024; no account creation endpoint.
Session tokens use secrets.token_urlsafe(32), only SHA256 hex stored in DB.
Absolute lifetime 8 hours. Logout revokes current session; internal revoke_all
supports revoking all sessions, without exposing an administrative endpoint.
Each lookup checks blocked account, linked archived employee, expiry, revocation
and credential_version, then loads roles and permissions from DB. No LEADER fallback.
Revocation is per request; an already executing request is not forcibly interrupted.

app/api/user_auth.py provides POST /api/auth/login, GET /api/auth/me,
POST /api/auth/logout. Only these routes are added in app/main.py.
No global middleware/dependencies change existing authorization behavior.
The running process was not restarted; routes will become available only after
an explicitly scheduled restart. No UI has been added.

Login requires same-origin Origin header and JSON with exactly login/password.
Request stream is bounded to 8192 bytes. Manual validation avoids echoing password
values through framework validation errors. Errors are generic, backend failures
return 503. Login returns a CSRF value; cookie token is HttpOnly, SameSite=Strict,
Path=/, max-age 8 hours. Secure is mandatory on HTTPS. HTTP allowed only for a
loopback hostname AND loopback peer. No public deployment is approved by this check.
Logout validates Origin and a session-bound HMAC CSRF value in X-CSRF-Token.
require_session_csrf is prepared for future mutating routes but NOT attached to them.
GET /me returns only user id/login/employee_id, roles, permissions and CSRF value.
Success/error auth JSON responses use no-store; no passwords/session tokens logged.

Ten failed logins per account or peer within 15 minutes cause 429. Counts are
stored as security events, with advisory transaction locks across workers.
Unknown accounts also verify a dummy Argon2 hash. Event keys hash login/peer;
no raw passwords, session tokens or login payloads are stored in event details.
Success, failure, logout and session revocation events are recorded.
