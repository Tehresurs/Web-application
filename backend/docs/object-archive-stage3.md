## API и правила

Для `/api/objects/{id}` и `/api/subobjects/{id}` добавлены:

- `POST .../archive`;
- `POST .../restore`;
- `PATCH .../activity-status` с `{"activity_status":"ACTIVE"}` (также SUSPENDED / COMPLETED).

Операции архивирования/восстановления повторяемы. Повторное архивирование не меняет время. Восстановление снимает признак и очищает время текущего архивирования. Статус деятельности независим и сохраняется.

Старый `DELETE /api/objects/{id}` теперь архивирует и возвращает `deleted:false, archived:true`; физического удаления через него нет. DELETE подобъекта остаётся недоступным. Удаление других справочников не менялось.

GET объектов и подобъектов поддерживает `archive=active|archived|all`. По умолчанию API сохраняет доступ ко всем архивным состояниям для совместимости исторических потребителей. У подобъектов дополнительно возвращается `parent_is_archived`; фильтр архива учитывает собственный и родительский архив. Прежний фильтр `include_inactive` по `is_active` остаётся независимым.

Архив родителя не записывает изменения в дочерние строки. Восстановление родителя не восстанавливает отдельно архивированные подобъекты.

Новые закрепления и датированные назначения проверяют архив на сервере под блокировкой читаемых объектов. Выбор нового объекта в билете также проверяется. Неизменённые исторические привязки сохраняются; восстановление билета с существующим назначением не запрещено. Перенос даты начала назначения требует повторной проверки доступности объекта. Матрица продолжает читать сохранённые факты и планы без фильтра по архиву.

Согласно согласованию, достоверные ежедневные отчёты, включая запоздавшие, сохраняются с архивными объектами/подобъектами. Проверка и сохранение возвращают `warnings`; интерфейс показывает предупреждение. Оно не отменяет остальные блокирующие проверки. Парсер и сопоставление архивные записи не исключают.

## Интерфейс

В существующей вкладке объектов добавлены фильтр «Действующие / Архив / Все», независимый статус деятельности, архивирование с подтверждением и восстановление. Архивные карточки и дочерние строки выделяются нейтральным фоном и текстом. Для выбора нового закрепления/объекта билета архивные объекты исключены. ## Ограничения

- Существующее правило `is_active` не отменено: неактивность подобъекта и архив — разные признаки. Для просмотра неактивных записей используется прежний соответствующий фильтр.
- История циклов архивирования отдельно не создавалась; `archived_at` описывает текущее нахождение в архиве и не используется как запрет запоздавших отчётов.
- При отсутствии требуемого прежними правилами закрепления ежедневный отчёт по-прежнему требует разрешения этого замечания. Архивное предупреждение не создаёт фиктивное закрепление и не обходит прочую валидацию.
- Существующие исторические связи сохраняются; архивирование не прекращает автоматически уже рассчитанный план.

Изменяющие проверки выполнялись только в изолированных схемах. Рабочие объекты не архивировались тестами. Преобразование объектов в подобъекты не реализовано; алгоритмы ЛУВР, матрицы, Word-парсера, Расстановки и аналитики не менялись.
