## Files and architecture

- app/auth_route_policies.json: 163 explicit method/path/handler/permission policies.
- app/auth_policies.py: registry loader and FastAPI included-router traversal.
- app/auth_protected.py: separate create_protected_app factory / ASGI wrapper.
- tests/test_auth_policies.py: isolated integration checks.
- scripts/check_auth_stage3.py: before/after working-schema verification.
- docs/auth-stage3-route-registry-2026-10-18.md: complete route inventory.
- this document.

Stage 2 service verifies live sessions and loads current roles/permissions from DB.
Only login is public. Own session routes retain stage 2 checks. All other HTTP
routes require a session and explicit policy. Unknown methods/routes/handlers deny.
WebSockets deny. Static assets require a session. Policy records are committed
explicit data, never inferred from HTTP method at runtime. Runtime handler identity
must match the audited record. Static policy is bound to StaticFiles/directory.
CSRF and same-origin checks precede allowed mutating requests, including POST export.
Client role/employee headers do not determine identity or permissions.
Authenticated principal is available in ASGI request.state.auth_user.
No default LEADER on failure. Matrix capabilities in this entry explicitly deny DK.
Protected responses have no-store, nosniff and frame denial headers.
Data reads and exports run under existing read-only connection context, reset finally.

## Matrix

SYSTEM_TECHNICIAN: data.read, data.create, data.update, excel.export.
OFFICE_MANAGER: data.read, excel.export.
Both: no deletion, users administration, settings updates, confirmation/approval,
annulment, archive/restore, bulk processing, report publication or DK assignment.
Directory metadata and ordinary production additions/edits are explicitly listed.
These are application permissions, not new PostgreSQL grants.

GET/POST LUVR Excel and deployment Excel are in-memory exports: both roles allowed.
Existing VOU XLSM and metadata/downloads are available to both roles.
POST VOU generation publishes archive state: denied to both, independently of export.

## Isolation incident and mitigation

An intermediate control found a changed construction_objects row fingerprint with
unchanged row count. Cause was not established; do not attribute it to an external
user or claim the whole development interval had no data changes. No test-prefixed
objects found in working schema. No working data was restored or corrected.
Automatic approval initially rejected rerunning write tests on isolation concerns.
Before rerun, independent barriers were added for psycopg.connect AND inherited
Connection.connect/MatrixConnection.connect; positional conninfo and conninfo keyword
are rejected. During test methods, only exact temporary database name can connect.
Actual barrier code was tested fully offline: 10 forbidden forms rejected, zero real
driver/network calls (barrier-offline.txt). Subsequent run was approved and passed;
it also checks both connection barriers with real classes. Final working schema
snapshot equality is confirmed. Intermediate discrepancy remains disclosed.
