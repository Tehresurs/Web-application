## Архив

Добавлен VouArchive в app/services/vou_archive.py.
Публикация сохраняет backend/output/vou/archive/<uuid>/report.xlsm и snapshot.json.
Снимок включает UTC-время формирования, период, пять реквизитов, данные подготовки,
контрольную сумму XLSM и результаты проверок генератора.

publish принимает только XLSM из output/vou с VBA и явно успешными проверками
excel_reopened, preservation_accepted, data_totals_match. Источник нельзя взять
из архива. Генератор должен передать реквизиты, использованные при заполнении,
а не перечитать изменённые настройки после формирования.

Каждая публикация получает новый UUID. Сначала записывается скрытый staging-каталог,
затем он атомарно переименовывается. Ошибка не публикует частичный результат.
Повторное и параллельное сохранение не перезаписывает предыдущие отчёты.
Изменения текущих настроек не изменяют архивный снимок.
Проверяется путь и SHA256 перед выдачей. Повреждённый файл не скачивается;
в списке выводится предупреждение. Автоматического удаления архива нет.

API чтения:
- GET /api/vou/reports — список, снимки реквизитов и предупреждения;
- GET /api/vou/reports/{id} — полный снимок;
- GET /api/vou/reports/{id}/file — готовый XLSM.

Добавлен раздел «Отчет ВОУ»: архив, скачивание, обновление и переход к реквизитам.
Архив сейчас пуст. Публикация вызывается только внутренним модулем; внешний API
не позволяет загружать произвольные файлы в архив. Подключение успешного COM-генератора
к publish остаётся следующей частью Б3; кнопки формирования пока нет.
