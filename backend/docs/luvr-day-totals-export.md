## Готовая часть

Существующий GET `/api/luvr/month?year=2026&month=10` дополнен `item.day_totals`: по одной записи на реальную дату месяца. Источник — только рассчитанные `employees[].days[]` сохранённого месячного состава.

Поля: date, full_count, half_count, travel_count, off_shift_count, downtime_count, dismissed_count, sick_count, unknown_count, present_people_count, work_equivalent.

Счётчики кодов используют только final_code. Присутствующие — FULL + HALF; эквивалент — FULL + HALF/2. Болезнь считается отдельно по is_sick. UNKNOWN учитывается только для итоговой пустой ячейки с final_source_type=UNKNOWN и без болезни: обычный выходной 5/2, пустота после увольнения и явный EMPTY override не становятся UNKNOWN.

На вход агрегации поступают только строки месяца; состав базы не запрашивается повторно. Сортировка строк не влияет на суммы. При override/сбросе существующая перезагрузка месяца обновляет и day_totals. Для несформированного/пустого состава возвращаются нулевые счётчики реальных дат; UI показывает итоги только сформированного месяца.

Итоговые строки размещены в tfoot той же таблицы под соответствующими днями. Отдельного scroll-container нет. Помимо пяти основных кодов доступны «Присутствуют», «Эквивалент», «Итого Уволен», справочные больничные и «Не определено».
