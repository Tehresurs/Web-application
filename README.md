# Техресурс

Веб-приложение для проверки ежедневных Word-отчётов, учёта билетов и ведения ЛУВР,
Производственной матрицы и Расстановки.

## Версия 8001

Ветка `development/8001` предназначена для отдельного экземпляра
`http://127.0.0.1:8001/`. Его исходники находятся в
`C:\Projects\excel-ai-agent-8001`. Изменения этой ветки не требуют изменения
запущенного экземпляра 8000.

Основной интерфейс обслуживает FastAPI: шаблоны находятся в
`backend/app/templates`, JavaScript и CSS — в `backend/app/static`.
Каталог `frontend` содержит отдельный проект Next.js; для основного интерфейса
обработки отчётов запускать его не требуется.

## Возможности

- Обработка папки Word-отчётов и одного файла `.docx`.
- Проверка сотрудника, объекта, ПО, категории и режима контроля перед сохранением.
- Справочники сотрудников, должностей, объектов, ПО и категорий.
- Билеты, движения сотрудников, календарь ЛУВР и Производственная матрица.
- Расстановка с выгрузкой Excel; по выбору — лист «Анализ» с таблицами и графиками
  в том же файле.

### Добавление одного отчёта

Во вкладке **«Обработка отчётов»** нажмите **«Добавить файл»** рядом с
«Запустить проверку» и выберите один `.docx`. Дата и сотрудник определяются из
отчёта. Проверьте распознанные значения, устраните замечания и нажмите
**«Сохранить результат»**.

«Замечания устранены» означает готовность к сохранению. Подтверждённый ежедневный
факт появляется после успешного сохранения; интерфейс показывает его номер.
Повторная загрузка того же подтверждённого файла показывает существующие факты
без дублирования.

Если для определённых сотрудника и даты уже есть факты, можно выбрать конкретный
источник для замены исправленным отчётом. Перед заменой показываются различия и
запрашивается подтверждение. Заменяются все строки выбранного исходного отчёта;
прежние факты и ручные корректировки сохраняются в архиве.

### Проверка и удаление факта

В Производственной матрице раскройте сотрудника и выберите день.
В карточке подтверждённого факта доступны:

- **«Проверить источник»** — номер факта, дата, сотрудник, объект, категория,
  исходный файл и причины предупреждений.
- **«Удалить событие за этот день»** — удаление только выбранного факта после
  подтверждения. Его данные и связанные ручные корректировки архивируются.
  Другие факты и билеты сохраняются; распределение времени пересчитывается.

Кнопка добавления файла находится во вкладке «Обработка отчётов».

### Правила учёта

- ЛУВР задаёт доступное рабочее время дня. Фактическое распределение по отчётам
  не превышает этот объём: например, 0,5 дня и два отчёта дают по 0,25.
- «Д» в ЛУВР означает нулевое рабочее время. Полученный отчёт сохраняется в
  истории, но не увеличивает учтённое время.
- Для должностей без обязанности сдавать ежедневный отчёт доступное время
  учитывается как камеральная работа; отчёты не распределяются по объектам.
- Режим контроля по умолчанию — инспекционный, с сохранением предусмотренных
  настроек должности. Выбранный вручную режим сохраняется до следующего изменения.
- У ПО можно задать, изменить или очистить категорию по умолчанию. Ручной выбор
  категории для конкретного отчёта сохраняется при повторной проверке.
  Смена настройки ПО не изменяет ранее подтверждённые отчёты.
- Проверка билетов учитывает полные даты и время, промежуточные календарные дни,
  направление поездки и аннулирование. Подтверждение одинаковых поездок защищено
  от дублирования.

## Запуск в Windows

Нужны Python с зависимостями из `backend/requirements.txt` и PostgreSQL.
Настройки подключения хранятся в локальных файлах окружения и не публикуются.

Для существующего локального экземпляра 8001 используется
`C:\Projects\run_report_review_8001.py`. Этот локальный скрипт запуска не входит
в репозиторий. Он выбирает профиль `APP_DB_PROFILE=test` и после загрузки
приложения устанавливает:

```text
DB_NAME=ai_excel_agent_test
DB_SCHEMA=test_construction_identity_stage46
APP_TEST_ALLOWED_DB_SCHEMAS=test_construction_identity_stage46
```

Перед подключением нужно проверить фактические `current_database()` и
`current_schema()`. Профиль test загружает `backend/.env.test`; не используйте
для него настройки базы экземпляра 8000.

Общая команда запуска из каталога `backend` при корректно подготовленном
окружении:

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

Миграции находятся в `backend/app/database/migrations`; вспомогательные
скрипты миграций — в `backend/app/database`. Для существующей базы применяются
нужные миграции по порядку с проверкой их назначения. В частности:

- `025_report_review.sql` — проверка отчётов и согласованные исключения.
- `026_po_default_category.sql` — категория по умолчанию у ПО.
- `027_matrix_report_replacements.sql` — архив заменённых отчётов.
- `028_matrix_fact_deletions.sql` — архив удалённых фактов.

Миграции 026–028 ограничены изолированной базой и схемой 8001. Не запускайте
их на базе экземпляра 8000. Для удаления фактов требуется применённая миграция 028.

## Проверки

Проверки JavaScript для сохранения отчётов и матрицы, из каталога `backend`:

```powershell
node --test tests/test_report_save.cjs tests/test_production_matrix.cjs tests/test_matrix_report.cjs
```

Адресные проверки Python находятся в `backend/tests`, включая
`test_matrix_report.py`, `test_matrix_luvr_budget.py`,
`test_po_default_category.py` и `test_rail_duplicate_guard.py`.
Тесты, использующие PostgreSQL, выполняются только с подготовленным тестовым
профилем; адресные проверки отчётов откатывают изменения данных.
Полный набор зависит от состояния тестовых справочников и базы.

`backend/input`, `backend/output`, `backend/uploads`, файлы окружения,
загруженные отчёты и билеты не должны попадать в Git.

## Перемещение сотрудников — локальный режим 8001

Реализованы постоянный перевод (включая задним числом), отдельное назначение
И.О. без замены основной должности и завершение И.О. с обязательным выбором
плановых объектов. Должности и объекты выбираются из существующих справочников.
История сохраняется; ошибочное незавершённое И.О. отменяется кнопкой
**«Удалить назначение И.О.»** с причиной и подтверждением. Завершённое назначение
со связанным планом защищено от такого удаления.

Должность и временное назначение определяются на дату ЛУВР, Матрицы,
Расстановки и ВОУ. Исходные карточки и снимок справочника совместимы с новой
историей: отсутствие старых записей переводов само по себе не вызывает
`POSITION_HISTORY_UNVERIFIED` и не придумывает дату первого назначения.
Подтверждённые фактические значения при этом не переписываются.

Текущий явно включаемый локальный запуск из корня проекта:

```powershell
.\backend.venv\Scripts\python.exe -B .\run_8001_personnel_local.py
```

Этот launcher слушает только `127.0.0.1:8001`. Кадровый модуль в локальном
режиме фиксирует источник **«Локальное приложение»** (`LOCAL_APP`), без
фиктивного пользователя или сессии. Проверяются Origin, Host, Fetch Metadata,
read-only, отдельный ключ процесса и фактический адрес/PID Windows TCP listener.
Проверка TCP выполняется непосредственно Windows API на каждом запросе,
без PowerShell и без кэширования результата. Кнопка появляется сразу;
проверка доступности и история загружаются параллельно.

Это локальный режим, **не готовый способ публикации в сеть**. Для сетевого
размещения требуется отдельно закончить защищённый вход и проверку разрешений;
локальный режим нельзя просто открыть внешним bind, туннелем или прокси.
Opt-in средства сессионного входа и изолированные прототипы безопасности
сохранены в репозитории, но не означают включённую сетевую авторизацию.

Для существующего экземпляра уже применены 033–035. Их повторный запуск
не нужен. На другой установке миграции требуют проверки целевой БД/схемы,
резервной копии и явного согласования; загрузка интерфейса их не применяет.
`date_readers_verified` подтверждается проверочным запуском, а не ручным
выставлением флага. Скрипты рабочих миграций, интеграционных прогонов и
подтверждения готовности не являются обычными безопасными smoke-тестами:
перед выполнением нужно прочитать их ограничения и условия.

Адресные проверки интерфейса из корня проекта:

```powershell
node --test backend/tests/test_personnel_button.cjs backend/tests/test_employee_workspace.cjs backend/tests/test_employee_card.cjs
$env:PYTHONPATH='backend'
.\backend.venv\Scripts\python.exe -B -m unittest discover -s backend/tests -p test_personnel_local.py -v
```

Во втором наборе сравнительная проверка Windows TCP API требует уже запущенного
локального 8001. Браузерные сценарии, создающие кадровые записи, выполняются
только на явно подготовленных синтетических данных, не на реальных сотрудниках.

## Локальные файлы, не входящие в репозиторий

Резервные копии PostgreSQL, журналы, браузерные профили, диагностические выгрузки,
фактические Word/Excel-отчёты и приватные настройки остаются вне Git.
Рабочий шаблон ВОУ `backend/templates/vou/*.xlsm` с деловыми данными также
передаётся отдельно; для соответствующего Excel-экспорта он должен быть установлен
локально. Чистый checkout сам по себе не содержит этот шаблон и рабочую БД.
